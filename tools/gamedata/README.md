# Справочники моделей

Четыре вопроса alt:V о моделях — `getVehicleModelInfoByHash`,
`getPedModelInfoByHash`, `getWeaponModelInfoByHash` и `vehicle.getModsCount` —
не может ответить ни игра у клиента, ни реестры сервера: это свойства самих
моделей, лежащие в файлах игры. alt:V держит их четырьмя двоичными файлами
рядом с собой; мы — одним, который собирает этот инструмент.

```powershell
python tools\gamedata\make_gamedata.py <каталог с .bin от alt:V> release\server\gamedata.bin
```

Файл необязателен. Нет его — сервер поднимается как прежде, а четыре вопроса
отказывают вслух и говорят, чего не хватает. Путь задаётся настройкой
`gamedata` в `server.cfg`; по умолчанию это сосед сервера.

## Раскладка чужих файлов

Восстановлена по самим файлам и сверена на них же: **каждый из четырёх
дочитывается ровно до последнего байта**. Это и есть проверка правильности —
раскладка, ошибшаяся хоть на байт, разъезжается и до конца не доходит.

У всех четырёх две буквы имени, два байта выпуска и дальше записи подряд, без
оглавления. Строки — длина и байты; у `vehmods.bin` длина двухбайтная, у
остальных однобайтная.

### `vehmodels.bin` — «VE», 882 записи

| поле | вид | что это |
|------|-----|---------|
| hash | u32 | joaat имени |
| name | str8 | `sultan` |
| info | 9 байт | род, колёса, бронестёкла, шесть цветов |
| kits | u32 | два номера наборов тюнинга: младший и старший, `0xFFFF` — нет |
| extras | u16 | какие дополнения кузова у модели есть |
| defaultExtras | u16 | какие стоят по умолчанию |
| autoAttachTrailer | u8 | цепляет ли прицеп сама |
| bones | u8 + записи | номер u32 и имя str8 на кость |
| canAttachCars | u8 | можно ли цеплять к ней машины |
| handling | u32 | joaat имени управляемости |
| dlc | str8 + u8 + u32… | набор и хеши |

Девять байт `info` ложатся на девять полей `IVehicleModel` alt:V один в один —
род, число колёс, бронестёкла и шесть цветов, — и это само по себе
доказательство, что байты опознаны верно.

Два признака развели списками, а не догадкой: прицеп сам цепляют сорок машин, и
среди них phantom, packer, bison, bobcatxl — тягачи и пикапы с фаркопом; машину
цепляют тринадцать: cargobob, towtruck и родня — эвакуаторы и вертолёт с крюком.

Номер набора тюнинга опознан сверкой имён: sultan даёт 45 — `39_sultan_modkit`,
zentorno 90 — `89_zentorno_modkit`, banshee 51 — `46_banshee_modkit`.

### `pedmodels.bin` — «PE», 1079 записей

hash u32, затем пять строк str8 (имя, род, набор, оружие без оружия, набор
движений), затем u16 костей и на каждую номер u16, место u16 и имя str8.

Ложится на `IPedModel` alt:V поле в поле.

### `weaponmodels.bin` — «WE», 182 записи

hash u32, имя str8, имя модели str8, хеш модели u32, хеш вида патрона u32, вид
патрона str8, **имя модели патрона str8**, хеш модели патрона u32, четыре u32
запаса патронов, вид урона str8, набор str8.

Выделенного поля нет в разборе, ходившем по сети, и без него всё дальнейшее
читается со сдвигом — с правдоподобными числами не на своих местах.

### `vehmods.bin` — «MO», 571 запись

Номер u16, имя str16, **число мест u8**, затем на каждое место: номер места u8,
число деталей u8 и сами номера деталей u16.

Числа мест в разборе, ходившем по сети, нет вовсе — оттого он не мог найти, где
кончается набор, искал следующий поиском строки `modkit` в потоке и терял девять
наборов из десяти.

## Наш файл

«OXGD», выпуск u16, словарь строк, затем четыре раздела подряд. Строки лежат
общим словарём, и это не украшение: `SKEL_Head` встречается 1079 раз, по разу на
модель человека. Сложенные как есть, имена костей занимают три четверти файла;
словарём — по разу, и файл выходит вдвое меньше исходных.

Читается он целиком и один раз, при запуске сервера, — оттого оглавления в нём
нет. Выпуск сверяется точным равенством, а не «не старше»: раскладка сплошная, и
файл другого выпуска разобрался бы не как ошибка, а как чепуха.

Оборванный файл и файл с лишним хвостом отвергаются целиком, а прочитанное до
обрыва выбрасывается. Половина прочитанного хуже, чем ничего: разницу между «этой
модели нет в игре» и «файл оборвался» изнутри режима не видно никак.

## Чем это проверено

Набором (`server/tests/game_data_tests.cpp`) — чтение, обрыв, хвост, чужой файл,
чужой выпуск, и отдельно разница между «набора тюнинга у модели нет» и «про
модель мы не знаем».

И живой игрой, самой крепкой проверкой из возможных: справочник говорит, что у
`police` по умолчанию стоит дополнение кузова номер два, — игра, у которой
спросили про заведённую машину, отвечает тем же номером. Сходятся не только
числа, но и нумерация битов.

## Чего здесь нет

`rpfdata.bin` alt:V зашифрован, и что в нём — неизвестно. Он не нужен ни для
одного из четырёх вопросов.

Чужие `.bin` в репозиторий не кладут, и порождённый файл — тоже: он собирается
тем, у кого есть исходные, и раздаётся вместе с сервером, как `libnode.dll`.
