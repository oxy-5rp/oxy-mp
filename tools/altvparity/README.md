# Машинные сверки с alt:V

Четыре скрипта, которыми паритет со слоем alt:V считается не на глаз. Каждый из
них однажды нашёл **молчащую** беду — то есть такую, у которой нет ни
исключения, ни строки в журнале, а наружу она выходит через несколько звеньев.

Все четверо разбирают `index.d.ts` из `@altv/types-server`, `-client` и
`-shared`. Живой набор объявлений лежит в `node_modules` любого режима под
alt:V; ниже он назван `$T`.

```powershell
$T = "D:\backend-VRUSSIA\node_modules\@altv"
$env:PYTHONIOENCODING = 'utf-8'   # иначе кириллица в выводе рассыпается
```

## `missing.py` — чего у нас нет вовсе

```powershell
python tools\altvparity\missing.py "$T\types-server\index.d.ts" `
    "script-js/js/*.js" "script-js/src/*.cpp" "server/src/*.cpp"
```

Ищет имена из объявлений в наших исходниках. **Ответ «нет» надёжен, ответ
«есть» — оценка сверху**: одноимённое поле могло попасться и в чужом месте.

**Клиентской сверке обязательно давать и общие файлы**, а не только
`client-js/`: `alt_enums.js` и `alt_shared.js` лежат в `script-js/js/`, но
собираются и в клиент тоже (`client-js/CMakeLists.txt`). Без них сверка
недосчитывается семи десятков имён и объявляет несделанным сделанное:

```powershell
python tools\altvparity\missing.py "$T\types-client\index.d.ts" `
    "client-js/js/*.js" "client-js/src/*.cpp" `
    "client/src/*.cpp" "client/src/game/*.cpp" `
    "script-js/js/alt_enums.js" "script-js/js/alt_shared.js"
```

## `used_by_mode.py` — чего нет из того, что зовёт живой режим

```powershell
python tools\altvparity\used_by_mode.py "$T\types-server\index.d.ts" `
    "D:\backend-VRUSSIA\src" "script-js/js/*.js" "script-js/src/*.cpp"
```

Главное число паритета. Общее в `missing.py` включает поезда, бронестёкла и
подвеску поколёсно — то, чего не трогает никто; здесь остаётся только то, на
чём режим споткнётся на самом деле.

## `shapes.py` — доводы конструкторов и методов

```powershell
python tools\altvparity\shapes.py
```

Пути внутри — от корня дерева. Сверяет **число доводов**: у alt:V перегрузки
объявлены отдельными строками, и совпадение хотя бы с одной — необходимое
условие.

**У самой сверки нашлось три слепых пятна, и все три чинились её же прогоном.**
Обобщённые методы (`setMeta<K extends string>(…)`) она не видела вовсе — а ими
объявлена вся семья метаданных. Запятые внутри `<…>` она считала разделителями
доводов, отчего у метода появлялись лишние варианты подписи, и любой из них
принимал что угодно. А громкий отказ (`throw` первой строкой) она объявляла
потерей довода — таких в слое десятки, и настоящие находки тонули среди них.

Нашёл четыре ошибки разом, и все молчали: размер маркера, съедаемый доводом
`useStreaming`; общность метки, не принимаемую вовсе; доводы `WeaponObject`,
разъезжающиеся с четвёртого; объектную форму `set*Meta`.

Ложные срабатывания у него есть и останутся: объявленный отказ (`absent`) стоит
без доводов, а перегрузка с одним доводом-объектом выглядит как расхождение с
парой «ключ и значение». Сейчас это `WebView.setExtraHeader`, `VoiceChannel.*`
и `setMeta` — их можно не читать.

## `binding_arity.py` — сколько доводов читает привязка

```powershell
python tools\altvparity\binding_arity.py "$T\types-client\index.d.ts" "client-js/js/*.js"
```

То же сравнение, но для того, что читает наш C++ и слой. Метод, объявленный с
меньшим числом доводов, теряет остальные **молча**: JavaScript лишних доводов не
замечает, и вызов удаётся. Нашёл `clearClothes`, раздевавший человека целиком
вместо снятия одной вещи.

## `native_arity.py` — сколько доводов у натива

```powershell
python tools\altvparity\native_arity.py "$T\types-natives\index.d.ts"
```

Сверяет раскладку доводов в `client-js/js/alt_natives_table.js` с объявлениями
alt:V. Таблица порождается из открытой базы имён CitizenFX, а база местами
отстала от игры: у `TASK_JUMP` в ней два довода, а в её же описании к нему
написано «Definition is wrong. This has 4 parameters».

Лишние доводы отбрасываются на границе **молча** — ни ошибки, ни строки в
журнале, а натив делает не то. Нашла сто тридцать три таких натива; после правки
осталось три, и в них больше объявлено уже у нас.

Правится не таблица, а её порождение: `EXTRA_ARGUMENTS` в
`tools/nativegen/nativetable.py`. Правка в готовой таблице пропала бы при первой
же пересборке.

## Чего они не заменяют

Ни один из четырёх не говорит, что найденное **работает**. Разошедшийся довод
они видят, а натив, отвечающий нулём, — нет; сверка `WeaponObject` прошла бы
чистой и на коде, который не заводил ни одного ствола. Живая игра остаётся
единственным способом это узнать.
