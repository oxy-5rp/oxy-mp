Образец, по которому сверяются, — установка alt:V 16.4.39 в

## 1. Меню внутри игры

Страница — `altv-ui` (Apache 2.0), лежит в `client/menu`. У alt:V она живёт в
кадре игры на CEF по ссылке `http://ui/index.html`; у нас так же.

- [x] исходники в проекте, зависимости ставятся сборкой
- [x] сборка страницы вписана в сборку проекта (`cmake/menu.cmake`)
- [x] локали `en` и `ru` — свои: репозиторий `altmp/altv-locales` с гитхаба удалён
- [x] мост `alt.on` / `alt.emit` в процессе отрисовки (`cefui/src/render_app.hpp`)
- [x] схема `http://ui/` (`cefui/src/ui_scheme.hpp`) — страница весит 4,6 МБ и в
      ссылку с данными не помещается
- [x] слой меню в кадре игры: второй браузер поверх слоя загрузки
      (`client/src/game/ui_layer.cpp`)
- [x] ввод: мышь, колесо и клавиатура доходят до страницы
      (`client/src/game/menu_input.cpp`); Escape открывает и закрывает меню
- [x] события моста со стороны клиента (`client/src/menu.cpp`):
      `loaded`, `version:update`, `version:setManifest`, `version:ready`,
      `settings:update`, `settings:change`, `ui:open`, `ui:ready`, `ui:toggle`,
      `ui:resetSkin`, `servers:recent:update`, `connection:*`, `exit`

Чего в мосте ещё нет и почему:

- **`connection:connected` не посылается.** Пока его нет, страница считает себя
  неподключённой и держит меню открытым поверх всего — так же ведёт себя alt:V,
  и это верно. Но у нас клиент подключается по слову лаунчера, ещё до своего
  запуска, и о состоянии сессии слой интерфейса сейчас не знает. Пока не
  связано, меню убирается Escape.
- **`connection:connect` не исполняется.** Сменить сервер на ходу — значит
  поднять сессию заново, а этого в клиенте ещё нет.
- **Список серверов, устройства записи, консоль.** Общего каталога серверов у
  oxyMP нет; недавние берутся из `skin.bin`.

## 2. Оформление из skin.bin

`skin.bin` у alt:V — это JSON: имя, значок, основной цвет, фоны, лента новостей и
список серверов. Страница получает его событием `version:setManifest` строкой
JSON с полями `name`, `rss`, `logo`, `uiBackground`, `primaryColor`, `servers`.

Цвет в файле записан с решёткой (`#FF6F5F`), а страница ждёт шесть знаков без неё
— alt:V решётку снимает, и мы обязаны снимать тоже.

- [x] чтение `skin.bin` (`config/src/skin.cpp`), проверки на образце alt:V
- [x] превращение в манифест — решётка у цвета снимается, лишнее странице не уходит
- [x] отправка странице событием `version:setManifest`
- [x] `ui:resetSkin` — возврат к обычному виду
- [ ] значок и имя окна лаунчера из него же

## 5. Подмена файлов игры

Самое ценное из найденного. В журнале alt:V:

```
Replaced x64/data/control/settings.meta
Replaced common/data/control/settings.meta
```

Это значит, что **alt:V не пересобирает RPF и не шифрует оглавление** — он
перехватывает чтение файла у игры и отдаёт свои байты. Отсюда следствие для нас:
работа по своим машинам, упёршаяся в шифрование оглавления RPF, идёт не туда.
Подбирать схему не нужно; нужно перехватить файловую систему игры.

- [ ] сверить механизм по исходникам CitizenFX (`D:\gtav-engine-reference`)
- [ ] перехват чтения файла у игры
- [ ] подмена `settings.meta`
- [ ] подгрузка DLC и своих архивов

## 6. Запуск копии игры

модулей стоит именно `backup\GTA5.exe`. У нас `backup/` пуст, а запускается
оригинал.

## Известное, но пока не сделанное

**Два полноэкранных слоя CEF стоят памяти.** Каждый отдаёт кадр обычным буфером
— до восьми мегабайт двадцать раз в секунду на слой. alt:V этого избегает общей
текстурой (`useSharedTextures` в его настройках). Пока не мешает, но при жалобах
на кадры смотреть надо сюда.
